DEVELOPMENT INSTALL
===================


File Permissions
================

Make sure the following directories exist and are writable:

- `/appfiles/sys/cache`
- `/appfiles/sys/logs`

Make sure the following files are executable:

- `/appfiles/bin/console`
- `/appfiles/bin/console-dev`
- `/appfiles/bin/install_vendors.sh`
- `/appfiles/bin/update_vendors.sh`


Download Vendors
================

Some vendors need to be downloaded separately. This is automated by the `/appfiles/bin/install_vendors.sh` shell script:

	$ cd appfiles/bin
	$ ./install_vendors.sh
	Initialized empty Git repository # etc

Note that this will pull the latest revision which might break. You may need to revert.


Edit Config
===========

Edit `/appfiles/config.php` with your database details.

Edit `/sys/config/config.yml` and find the line for `assets_base_urls` and edit it for your web path. (This won't be necessary soon, but needed for now).


Run Dev Commands
================

From the console, run the two dev commands.

To create the database and schema:

	$ cd appfiles/bin
	$ ./console-dev dpdev:new-install

To fill in the default data:

	$ ./console-dev dpdev:new-install-data


NOTES:

- The `dpdev:new-install` command will drop the database if it doesn't exist.
- The `dpdev:new-install` command dynamically generates the schema based on the defined entities. If an entity is incorrect/invalid, then the command will fail. You'll need to either fix the bug or revert to a previous working revision.
- The `dpdev:new-install-data` creates an admin user with email "admin@example.com" and password "pass".


Log In
================

View `/index_dev.php/tech/` in your browser.

See `/appfiles/Application/TechBundle/Resources/config/routing.yml` for more URLs you can try (they are prefixed with `/tech/`).
